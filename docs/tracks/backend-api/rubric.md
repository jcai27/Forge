# Backend API Rubric

## Dimensions

| Dimension | Weight | What strong looks like |
| --- | --- | --- |
| Correctness | 35% | Acceptance tests pass and edge cases are handled cleanly. |
| Architecture quality | 20% | Data model and handler design are coherent and easy to extend. |
| Code organization | 15% | Changes are easy to navigate and responsibilities are not muddled. |
| Debugging strategy | 10% | Candidate iterates with tests and focused inspection instead of random edits. |
| Tradeoff awareness | 10% | Candidate can explain what they optimized for and what they deferred. |
| Explanation quality | 10% | Write-up and review notes are concise and technically sound. |

## Reviewer notes

- Do not punish AI usage by itself.
- Focus on whether the candidate stayed in control of the solution.
- Flag suspicious workflow patterns, but do not auto-disqualify without second review.
